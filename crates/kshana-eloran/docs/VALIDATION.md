# kshana-eloran validation ledger

PROPRIETARY — Kshana Pro.

This ledger lists every model and capability of the crate with its evidence label, the
reference it is checked against, the test that checks it, the tolerance of that test and the
known limitations. The facts are taken from the module documentation and the tests of the
crate; where a module says NEEDS CONFIRMATION or MODELLED, so does this ledger.

## Labels

| Label | Meaning |
|---|---|
| **VALIDATED** | An independent external reference (a published specification value, a published test case or test vector, a published reference curve) is reproduced by an automated test within the stated tolerance. |
| **MODELLED** | Implemented from the cited theory or literature and checked by internal tests (self-consistency, limits, conservation, round trips, comparison with the simulator's own truth), but not against an independent external reference. |
| **UNTESTED ON HARDWARE** | Code that drives real hardware and has only been compile-tested. |

"Internally verified" in the reference column means the test compares the code with its own
definition or with the simulator truth (exact by construction), not with an outside source.
A model is never VALIDATED by a test against data the model was tuned to, except where the
calibration is stated (seawater SF, below).

Test locations: `src/<file>::<test>` is a unit test in that file's `tests` module;
`tests/<file>::<test>` is an integration test of the crate.

## Requirements coverage

Status: **Built+tested** — implemented and covered by automated tests in this crate (or the
repository); **Built (needs hardware/data to verify)** — implemented, but its performance can
only be confirmed with hardware, external data or recorded signals; **Not built** — absent.
"Tested" means the tests listed in the ledger; it does not upgrade a MODELLED label.
