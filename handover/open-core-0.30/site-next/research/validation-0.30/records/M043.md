# M043 (matrix row 95): Lunar joint multi-technique OD and clock

Batch B2, branch `feat/val-b2`. Verdict: **BLOCKED** (stays MODELLED). No comparison was run.

- Pre-registered oracle (plan): Orekit 12.2 Range and InterSatellitesRange models generate the
  observations, Orekit BatchLSEstimator and Kshana both solve; VLBI by the M038 route; recovered
  states 1e-6 m, clocks 1e-15 s.
- Precondition (pre-registered in `B2-PREREGISTRATION.md`): Kshana's joint solve must accept
  observations it did not generate. It does not: `lunar_combination::estimate(cfg)` builds its own
  truth, forward model and noisy observables internally; `Network`, `forward`, `truth_state` and the
  nominal geometry are private, and no public function takes an observation vector. Running the
  oracle would need a new public entry point in `src/lunar_combination.rs`, which is feature work,
  not a defect fix, so outside this batch's licence.
- Even with an entry point, two facts make 1e-6 m agreement unreachable as the model stands:
  (1) the VLBI leg rides on the M038 delay model, which differs from ANISE by up to 24 us (M038
  record); (2) Kshana's ranges are instantaneous Euclidean distances, whereas Orekit's Range models
  solve the signal flight time, which for moving satellites differs by metres (lunar-local) to
  hundreds of metres (Earth station to satellite). These are expectations, not measurements.

  for 0.31; otherwise the row stays MODELLED.
