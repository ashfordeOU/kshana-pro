## Adversarial verification (2026-10-01): DOWNGRADED, stays MODELLED

The test passes (732 splits), but the comparison does not test the least-squares linear algebra
the row claims. Every committed `delta_y` is built as `E . delta_s`, so it lies exactly in range(G)
(`delta_y = G [-delta_s; 0]`). For such an input, ANY left inverse of G returns
`blind_dx = [-delta_s; 0]` and a zero parity residual. Measured on the committed fixture:
the numpy `blind_dx` equals `[-delta_s, 0]` to 5.8e-15 m, and an arbitrary wrongly weighted
(oblique) left inverse reproduces the fixture to 4.9e-15 m. On a residual with a parity part, that
oblique estimator differs from least squares by 0.17 m. Mutation in a scratch copy: replacing the
engine's projector with `S + K (I - G S)` (K arbitrary, not least squares) leaves this test GREEN,
while two lib unit tests go red. The comparison therefore reduces to the identity S G = I (an
internal identity, which the promotion rule excludes), with the inputs' own sign flip as the
"oracle". The 1e-3 relative bar is also loose for a linear solve: a 0.1 % engine error passes.
Remedy for a later round (a new comparison, new pre-registration): a committed `delta_y` with a
parity component (for example real-data common mode plus independent per-satellite errors) and a
linear-algebra tolerance such as 1e-12, in a new `tests/<slug>_oracle.rs`.
