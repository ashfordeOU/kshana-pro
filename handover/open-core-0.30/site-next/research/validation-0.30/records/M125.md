# M125 (matrix row 211): Single-frequency ionospheric and UTC services of a LEO navigation message

Verdict: **BLOCKED** (stays MODELLED). No comparison was run.

- Planned oracle (VALIDATION-0.30-PLAN.md, B7): Galileo NeQuick G JRC reference implementation
  (EUPL-1.2, run as a tool) for Az; the GPS and Galileo ICD worked cases for the three
  leap-second UTC cases. Tolerance fixed by the plan: Az 1e-6 sfu; UTC 1 ns across the three cases.
- Blocker (plan, "Known blockers"): NeQuick G JRC needs a registration at the European GNSS
  Service Centre (https://www.gsc-europa.eu/node/6921); it is not installed in
  ~/Code/kshana-oracles (README "Not installed, on purpose"). gnsstk, the alternative the study
  names for the UTC cases, is not installed either. Batch brief: leave the row MODELLED.
- Observation for the owner (no comparison run): `services::effective_ionisation_level` takes
  the modified dip latitude as an input and returns the closed form `ai0 + ai1 mu + ai2 mu^2`
  with the all-zero and [0, 400] sfu rules; a NeQuick G Az comparison on the same mu checks a
  quadratic. A comparison with weight would be on the MODIP grid interpolation and the STEC
  validation table of the Galileo single-frequency algorithm document (issue 1.2, Annex), which
  Kshana does not implement (the module says so). The IS-GPS-200 and Galileo OS SIS ICD give the
  UTC cases as formulas, not as printed numeric examples, so "the ICD worked cases" may not exist
  as P1 values; gnsstk (LGPL-3.0, run as a tool) is the practical UTC oracle.
- To unblock: register at the GSC and install NeQuick G, or rescope the row to the UTC cases with
  gnsstk installed.
