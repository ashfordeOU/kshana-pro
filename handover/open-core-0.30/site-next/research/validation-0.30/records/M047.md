# M047 (matrix row 102): Lunar interoperability export, scoped to interchange conformance

Batch B1, branch `feat/val-b1`, worktree `~/Code/kshana-wt-val-b1`.

## Pre-registration (written 2026-10-01T03:25Z, before any comparison was run)

Oracle kind: **Library**. Two independent readers of the Kshana-written lunar CCSDS OEM files
(`tests/fixtures/lunar_interoperability_export/kshana_lunar_moon_me_ltc.oem` and
`kshana_lunar_moon_pa_tcl.oem`, which the existing test requires to be byte-identical to today's
`lunar_interop::export_lunar_oem` output):
1. `oem` 0.4.5 (MIT, https://github.com/bradsease/oem, PyPI `oem==0.4.5`);
2. Orekit 12.2 (Apache-2.0, https://www.orekit.org) `ParserBuilder().buildOemParser()` with default
   (strict) settings, via a committed Java driver.

Claim (narrowed to interchange conformance): the files decode in both readers to the same header and
metadata tokens and the same states.

Tolerances (fixed now): tokens exact (OBJECT_NAME, OBJECT_ID, CENTER_NAME, REF_FRAME, TIME_SYSTEM,
START_TIME, STOP_TIME, CCSDS_OEM_VERS, ORIGINATOR) in each reader; number of states equal; every
decoded epoch equal to the written epoch to 1 microsecond (the written precision); every decoded
position within 5e-7 km and velocity within 5e-10 km/s (half the last written digit) of Kshana's
in-memory state, in each reader. If a reader refuses either file, the comparison fails for that
reader and the row is not promoted (the refusal is the finding).

Test: `tests/lunar_interop_oem_oracle.rs::lunar_oem_decodes_identically_in_two_independent_readers`;
fixture `tests/fixtures/lunar_interop_oem_oracle/`.

## Result

**Verdict: DISAGREES (a reader refuses). STAYS MODELLED.**

- `oem` 0.4.5: both files decode; tokens, 9 + 9 states and epochs within the pre-registered bounds;
  it warns "Unsupported TIME_SYSTEM 'ltc' ('tcl'), falling back to DateTime".
- Orekit 12.2 `OemParser` (strict defaults): **refuses both files**: "use of time system LTC (TCL) in
  CCSDS files requires an additional ICD and is not implemented in Orekit". Positive control: the same
  driver decodes Kshana's EME2000/UTC OEM (`tests/fixtures/ccsds_oem_interop/kshana_leo_eme2000.oem`).
  Diagnostic (not a comparison): with TIME_SYSTEM replaced by TDB, Orekit decodes both, passing
  REF_FRAME MOON_PA / MOON_ME through, so the refusal is the lunar time-system token alone.
- Finding: the lunar time systems LTC and TCL that Kshana writes are not readable by Orekit 12.2 and
  only nominally by oem 0.4.5; interchange of these files with mainstream CCSDS readers is not
  established. The plan-named test is committed ignored with that reason; the live test
  `tests/lunar_interop_oem_oracle.rs::recorded_two_reader_outcome_is_for_todays_export` pins the
  outcome to today's export. Fixture: `tests/fixtures/lunar_interop_oem_oracle/`.
