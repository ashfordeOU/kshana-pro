### Pre-run refinement (2026-10-01T03:40Z, still before any comparison was run)

Reading the sigmf-python 1.13.0 source (`SigMFFile.set_metadata`) showed that on reading any
file it overwrites the reported `core:version` with its own specification version (keeping the
file's value as `_declared_version`) and inserts `core:num_channels = 1` when the file omits it
(the specification's default). Comparison 3 therefore takes `core:version` from
`_declared_version`, and where Kshana omits `core:num_channels` it requires sigmf-python's value to
be the default 1. No tolerance changed; this fixes which sigmf-python attribute is read.

Finding worth noting (not a defect): `sigmf::read` treats the first capture's `core:sample_start`

`sample_start * sizeof(sample)` in the file, so this is a conforming reading.
