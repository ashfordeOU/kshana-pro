- Tolerance (fixed before the run): (a) >= 100 epochs and 3-D error <= 3 m at >= 95 % of epochs;

- Observed: 280 epochs solved; 3-D error median 1.53 m, 95th percentile 3.31 m, max 4.38 m;
  261/280 = 93.2 % within 3 m: **fails (a)**. ISB median difference -0.351 ns: **passes (b)**
  (per-epoch 95th percentile 2.63 ns, reported only). Kshana-RTKLIB position difference median
  0.64 m, 95th percentile 1.59 m (reported only).
- Finding: RTKLIB itself, on the same slices, has 88.2 % of 287 epochs within 3 m (95th percentile
  3.51 m), so the 3 m / 95 % bar is beyond single-frequency broadcast-ephemeris, Klobuchar
  positioning at this low-latitude station on this day; the miss is the error budget of the
  inputs, not a solver discrepancy (Kshana is closer to ITRF2020 than RTKLIB). A dual-frequency,
  ionosphere-free GPS+Galileo comparison would test the solver with the bar the plan set, but
  `pvt::assemble_epoch` forms no Galileo ionosphere-free pair (its L2 code list has no E5a/E5b
  code), so that comparison needs a change outside this batch's modules. Not re-run with any
  other tolerance.
