- Planned oracle: CODE GIM `CODG1330.18I` with CODE DCBs, against geometry-free slant TEC from
  the real ABMF dual-frequency code observations (Reference).
- Blocker (structural, found before any comparison): the row's capability is computed inside
  `leo_pass` from the engine's own modelled band delays,
  `(iono_delay_1 - iono_delay_2) * k_gf / TECU` in a private closure of `src/leo_pass.rs` (around
  line 2895). No public Kshana function takes measured code pseudoranges, so the GIM can only be
  compared with Kshana's code by adding an observation-level entry point to `src/` (for example a
  `pub fn geometry_free_stec_tecu(p1_m, p2_m, f1_hz, f2_hz)` that the report also calls). The plan
  lets a batch edit `src/` only to fix a defect an oracle exposed, so this is an owner or
  integrator decision. A test that computed the geometry-free formula itself and compared it with
  the GIM would be our own second implementation and cannot promote the row.

  header gives satellite C1W-C2W (P1-P2) biases and an ABMF station bias of 23.476 ns for C1C-C2W;
