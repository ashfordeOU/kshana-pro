# D11: clock-ensemble Kalman 3-sigma bound is optimistic once flicker floors are on

Status: fix in progress (public branch fix/clock-d11-flicker-bound, draft PR to follow); fusion needs a follow-up (D11c). Found 2026-10-08 by W6 while regenerating docs/assets/clock-ensemble-band.svg.

## Reading
- The error grows with the flicker floor, but the filter's reported bound does not. The two-state filter does not model the flicker term.
- NIS/NEES are bit-identical with and without the floor. So the consistency check runs on a model without the flicker term, and it reports a matched filter while the coverage says otherwise.
- 67fed19e's test asserts that the floor worsens p95 coast. It does not assert the 3-sigma coverage.

## Fix direction (to be pre-registered before coding)
- Either model flicker in the filter (e.g. an added state or a process-noise inflation), or state the bound as not covering flicker.
- Add a coverage bar, pre-registered: 3-sigma coverage ≥ 0.99 on the shipped scenario.
- Make NIS/NEES see the truth model, including flicker.


## Cause (confirmed 2026-10-08, W5)
- `run_clock` (src/run.rs): the truth clock is `ClockModel::new(..).with_flicker(floor)` (an OU bank, tau 1 s to 1e5 s, 4 per decade, flat ADEV = floor). The bound is the two-state `KalmanClock::phase_sigma()`, which has no flicker term.
- `filter_health::assess` draws its own truth from the filter's two-state Q and has no flicker input, so NIS/NEES were matched by construction and identical with and without the floor.
- The series being bounded is the deterministic `HoldoverEstimator` predictor's error. It knows nothing of the flicker frequency, so the right bound is the unconditional one. A filter with flicker states updated during the 600 s of GNSS sync would learn the flicker frequency and give a bound that is too tight for this series.

## Fix
- Bound = two-state variance + `Flicker::phase_variance_after_steps(n, dt)`: the exact variance of the phase the truth bank's own AR(1) components accumulate over the `n` steps since the last sync (stationary start). Same object as the truth, so truth and bound cannot drift apart. Zero without a floor.
- `filter_health::assess_with_flicker` / `assess_flicker_unmodelled`: truth drawn from the extended model, matched `ClockStateExt` with the truth's own bank (`ClockModel::flicker_bank`). NEES is on the (phase, frequency) marginal, two degrees of freedom. Run size with a floor: 16 seeds x 60 steps.
- `ClockStateExt::predict` / `update_phase` skip exact-zero terms (bit-identical), which keeps a 24-state assessment cheap: the shipped ensemble takes about 5 s.
- Floor-0 paths are untouched.

### B4 withdrawn, B4' set by the coordinator
- B4 (coverage <= 0.9995) is **withdrawn**: it sits inside the metric's own sampling noise (std about 0.0037 against a 0.0022 margin below 1), and the exploratory prototype's 0.99968 would have failed it. I ran that prototype before the bars were in the test header; it counts as exploratory only. The withdrawal is a post-hoc change and is recorded as one.
- **B4'** was set by the coordinator before anyone computed it: pooled RMS of (error / 1-sigma bound) over all outage samples and runs in [0.8, 1.2] for each clock, on the shipped scenario (seed 42) and on a fresh seed (7), 200 runs each. A priori basis: near-fully-correlated runs give about one chi-square(1) draw per run, so over 200 runs the RMS has std about 0.05 and [0.8, 1.2] is about +-4 sigma; it still catches a bound inflated by more than 1.25x. The test was committed (1752c032) before it was run.
- Result: seed 42 quantum 0.9450, classical 0.8886; seed 7 quantum 0.9028, classical 0.9333 (132,200 outage samples each). PASS, all slightly below 1 (the bound is mildly conservative).
