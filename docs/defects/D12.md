# D12: default hand-off acquisition on 100 ms tiered codes needs GBs of memory

Status: open. Found 2026-10-08 by W5 while moving the signal matrix onto the engine's default acquisition path.
Owner: W1b, together with B3.4 (acquisition surface), on the #45 line.

- `iq::acq::acquire` always builds and returns the full Doppler × code-phase grid (`AcqGrid`), so memory is O(bins × samples).
- With the default full tiered replica and auto coherent length:
  - Galileo E1-C (100 ms full period) needs about 2.4 GB;
  - Galileo E5a-Q (100 ms, 25 MS/s, 6.7 Hz bins, 601 bins × 2.5M lags × 8 B) needs about 12 GB, and the process is SIGKILLed on a 16 GB host.
- This predates D8: the textbook step is already 6.7 Hz there, and the D8 cap does not bind.
- The matrix keeps a primary-only replica for E1-C and E5a-Q until this is fixed. The reason is stated in the harness.

Fix direction: grid-free acquisition (a running best per bin or lag, plus peak, second peak and statistic) by default. The full grid is built only when an exported surface is requested, subject to a size cap.

Bars, to be pre-registered:
- AcqResult bit-identical to the grid path on L1 C/A, E1-B and E5a-I;
- peak RSS ≤ 256 MB for a default E5a-Q 25 MS/s acquisition.
