The open-core split

What is open vs. private, and the boundary between them.
kshana — public engineopen · reproducible
github.com/ashfordeOU/kshana · AGPL-3.0-only (+commercial)
▸
The simulation engine & capability code: PNT physics, estimators, detectors, the quantum-PNT verticals.
▸
verification.rs honesty matrix + the externally-validated test islands.
▸
CLI, Python bindings (PyO3) & WASM; every result reproducible from (inputs, seed, engine version).
▸
Ships nothing tender-specific — it models the class of system on public-source parameters.
⟶overlays · cites⟵
kshana-pro — private overlaybid · commercial
github.com/ashfordeOU/kshana-pro · PRIVATE
▸
Bid evidence for ESA tenders (lunar-PNT, 13503 quantum-PNT) — citing the public islands, never duplicating engine code.
▸
Research papers (arXiv drafts), the verified validation-dataset catalog, roadmaps.
▸
Commercial: legal (EULA/DPA/SOW), pricing, GTM kits, scenario-subscription packs.
▸
Private-only framing & numbers; the public repo stays clean of bid-specific claims.
The boundary rule. Capability → public (so it is open, auditable, reproducible). Evidence, papers, money → private. A result is labelled Validated only when an external-dataset oracle backs it; everything else is Modelled. That discipline, enforced in the open repo, is what the private bid evidence stands on.
