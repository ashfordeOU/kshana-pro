## 1. Purpose & scope

This is the **sizing-and-benefits** half of Ashforde's Phase-0/A contribution: given a
candidate LEO IOD orbit envelope and a target coverage/integrity KPI, (a) size the minimum
satellite count that meets the KPI, (b) trade the design grid (planes × satellites ×
inclination) for coverage / dilution-of-precision / revisit, and (c) quantify the benefit of
a *reconfigurable* PNT payload — the "app-store-for-space" value — over a fixed-function
constellation.

**Honest boundary.** Ashforde is a **consortium-SME work-package contributor — never prime,
never a mandated Key Person.** It sizes the *geometry and achievable performance* of the
candidate architecture; it does **not** own the spacecraft bus, the RF/payload hardware, the
reconfigurable-payload engineering, the launch/deployment plan, or the full mission concept.
The "app-store-for-space" / spacecraft-as-a-service *platform* is partner/programme-owned
(an explicit WP-A exclusion); Ashforde quantifies the *PNT benefit* of reconfigurability, it
does not build the reconfiguration mechanism. **TRL ~3, no flight heritage, no certification,
no ESA endorsement.**

## 2. The open-core sizing engine (runnable today)

Every sizing claim in this note runs through four built, tested functions in the open
Apache-2.0 core (`kshana/src/walker.rs`; capability map row "Constellation design",
`kshana/docs/CAPABILITY.md`). These are not slideware — a reviewer can run them line-by-line.

| Function (`kshana/src/walker.rs`) | What it computes | Honesty status |
|---|---|---|
| `min_satellites_streets_of_coverage(altitude_km, min_elev_deg, sats_per_plane)` | Idealised streets-of-coverage minimum-satellite sizing for continuous single global coverage: per-satellite Earth-central coverage half-angle `λ`, per-plane street half-width `c`, minimum plane count `p = ⌈π/(2c)⌉`, total `p · sats_per_plane`. | **modelled** (Rider/Beste closed forms, hand-verified) |
| `pdop_sweep(altitude_km, planes_grid, sats_grid, inclination_grid, …)` | Trade table over the `{planes × satellites × inclination}` grid: per cell, the **coverage fraction** (share of time a ≥4-SV fix with non-singular geometry exists) and the **median / worst PDOP** seen from a ground station over the window. | **modelled** (geometry on the 4.12 mm-validated SGP4 core) |
| `coverage_revisit(sats, station, step_s, duration_s, mask_deg, min_sats)` | Per-ground-point service FoM: coverage fraction and the **max / mean revisit gap** (longest stretch with fewer than `min_sats` in view). | **modelled** |
| `optimize_walker_design(…, objective)` | Gradient-free grid optimiser that returns the winning cell + the full ranked table under `MinSatellitesForCoverage{min_fraction}` / `MaxCoverage` / `MinWorstPdop`; deterministic, so the chosen design is reproducible. Validated to return the brute-force winner. | **modelled** |

Two properties make these defensible inputs to a study that must survive a GATEKEEPER and an
ISRR: (1) the geometry is propagated through the **same SGP4 path validated to 4.12 mm**
against the 666 AIAA 2006-6753 vectors, not a throwaway analytic propagator; and (2)
`optimize_walker_design` is **deterministic** — the chosen design is reproducible (carries a
`scenario_hash`), so the trade can be re-run and audited rather than re-asserted.

## 3. Sizing the minimum satellite count (D1.3 input)

### 3.1 Method — streets-of-coverage minimum-satellite estimate

For a representative target — *continuous single global coverage at a stated elevation mask* —
`min_satellites_streets_of_coverage` returns the idealised minimum. The geometry chain is:

1. Coverage half-angle `λ = arccos((Re/(Re+h))·cos ε) − ε` (Wertz *SMAD* / Rider 1985 slant
   triangle) — how big a cap each satellite serves above the mask `ε`.
2. Street half-width `cos c = cos λ / cos(π/s)` for `s` satellites per plane — the band the
   plane keeps continuously in view; returns *no street* when `λ < π/s` (satellites too sparse).
3. Minimum plane count `p = ⌈π/(2c)⌉` for evenly-spaced near-polar planes; total `= p · s`.

### 3.2 Illustrative numbers (modelled, representative — NOT a NAVEX design)

The shipped unit test `streets_of_coverage_sizes_a_global_constellation`
(`kshana/src/walker.rs`) pins a worked example that doubles as the method demonstrator:

| Input (illustrative) | Value |
|---|---|
| Altitude | 20 180 km (a MEO-reference point, used because it has a hand-verified test) |
| Elevation mask `ε` | 5° |
| Satellites per plane `s` | 4 |
| **Coverage half-angle `λ`** | **≈ 71.16° (1.2420 rad)** |
| **Street half-width `c`** | **≈ 62.83° (1.0965 rad)** |
| **Minimum planes `p`** | **2** |
| **Minimum total** | **8 satellites** |

A denser plane (`s = 8`) widens the street, so it needs **no more planes** — the function
returns `planes ≤ 2`, the expected monotone behaviour. The companion test
`streets_of_coverage_rejects_under_population` shows the **honest failure mode**: at **500 km,
10° mask, 3 satellites/plane**, `λ ≈ 14°` is too small for `λ < π/s` and the function returns
**`None` — no continuous street, no global sizing** rather than a false number.

> **Why these specific numbers, stated plainly.** The 20 180 km / 8-satellite figure is a
> hand-verified *method* demonstrator, not a LEO IOD design — a real NAVEX-class LEO
> constellation sits much lower, needs many more satellites for continuous coverage, and is
> sized from the real orbit envelope and KPI in the SoW. The note also surfaces an **open
> residual**: the idealised estimate omits the seam-exact Rider correction at the
> counter-rotating plane boundary (which can nudge the real minimum up by a plane); the
> seam-sensitive minimum-satellite solver is a documented follow-on (capability map).

### 3.3 LEO-IOD sizing — how this runs against the real envelope

For a representative **LEO PNT** band (e.g. ~1 000–1 500 km, near-polar to mid-inclination,
5–10° mask), the WP-A flow is:

1. **Bound the minimum** with `min_satellites_streets_of_coverage` at the candidate altitude
   / mask / satellites-per-plane (the analytical floor).
2. **Refine on real geometry** with `optimize_walker_design(objective =
   MinSatellitesForCoverage{min_fraction})` over the `{planes × satellites × inclination}`
   grid for the actual service region (a regional ground-station / user set is the realistic
   NAVEX-IOD case, not whole-Earth), returning the smallest design that meets the coverage KPI
   plus the full ranked table.
3. **Check service quality** with `coverage_revisit` (max/mean revisit gap) and the PDOP
   columns from `pdop_sweep`, so the chosen design is justified on availability **and**
   geometry **and** revisit, not satellite count alone.

The output is a **D1.3 trade table** (every grid cell: total satellites, coverage fraction,
worst-case PDOP, max/mean revisit) with the recommended design flagged and a `scenario_hash`
so the prime's SE function can re-run it. Because the inputs (altitude, mask, grid, region) are
the SoW's, the *numbers* are filled at WP execution; the *method and engine* exist and are
tested today.

## 4. The concept trade — fixed vs reconfigurable PNT (D1.3 justification)

A 13494 demonstrator's central concept choice is **fixed-function** vs a **reconfigurable /
"app-store-for-space"** PNT payload. Ashforde's contribution to the trade is the
**performance/resilience axis** — quantified, not asserted — alongside the partner-owned cost,
mass, complexity and platform-engineering axes.

| Concept axis | Fixed-function PNT | Reconfigurable PNT ("app-store") | Ashforde-quantified? |
|---|---|---|---|
| Coverage / PDOP / revisit at IOD | sized once for the launch waveform plan | same geometry; the payload *function* can change in orbit | **yes** — `pdop_sweep` / `coverage_revisit` / `optimize_walker_design` |
| GNSS-denied / contested resilience | fixed mitigation; re-spin needs a new build | new anti-jam / detection logic uploaded post-launch | **yes** — resilience FoM (jamming `availability_under_jamming`, RAIM/ARAIM protection levels) |
| Spectral / waveform agility | locked at design freeze | re-allocatable in service | **partner** (payload HW / SDR) — Ashforde models the *resulting* link/FoM only |
| Bus, mass, power, thermal | — | — | **partner** (bus WP) |
| Reconfiguration mechanism, secure in-orbit update | — | — | **partner / programme** (out of WP-A scope) |
| Platform / spacecraft-as-a-service business model | — | — | **out of scope** (programme-owned) |

The disciplined claim Ashforde can defend: a reconfigurable payload's **PNT benefit is the
performance/resilience headroom it buys after launch** — the ability to lift
`availability_under_jamming`, tighten an integrity protection level, or re-target a detection
operating point **without re-flying hardware** — and that benefit is exactly the FoM delta the
engine computes between a baseline configuration and an uploaded one.

## 5. Quantifying the reconfigurable-PNT benefit (D1.1 benefits analysis)

The D1.1 benefit case is built as a **before/after FoM delta**, each side a reproducible,
scenario-hashed run, each number labelled modelled.

### 5.1 The benefit metrics (all from the open core)

| Benefit dimension | Metric | Engine source | Status |
|---|---|---|---|
| Availability uplift | Δ coverage fraction / Δ `availability_under_jamming` between configs | `kshana/src/walker.rs`, `kshana/src/jamming.rs` | modelled |
| Integrity uplift | Δ HPL/VPL (protection level) at fixed P_HMI | `kshana/src/raim.rs` (`snapshot_raim`, ARAIM budget) | modelled (RAIM/ARAIM core itself is validated vs real IGS SP3) |
| Accuracy / timing | Δ positioning / timing FoM | `kshana/src/fom.rs` (`positioning_performance`, `score`) | modelled |
| Resilience under contest | Δ % availability under a jamming scenario; error growth under outage | `kshana/src/jamming.rs` + resilience models | modelled |
| Detection adaptability | Δ achievable Pd at fixed Pfa when a new detector is uploaded | `kshana/src/impairment_eval.rs` (ROC/AUC, `confusion_at`) — WP-B | validated (testbed); labels are model-derived |

### 5.2 Illustrative benefit framing (representative, NOT validated)

A representative D1.1 statement Ashforde could populate (numbers are placeholders to be filled
from the sized design and the SoW RF-environment):

> *"For the sized LEO IOD design, uploading a revised anti-jam configuration is modelled to
> lift `availability_under_jamming` from X% to Y% against the reference jamming scenario, and
> to tighten the snapshot-RAIM HPL from A m to B m at a fixed P_HMI allocation — a benefit
> obtainable in service, without a hardware re-flight. Each figure is reproducible
> (scenario-hashed) and tagged modelled; the RAIM/ARAIM core producing the protection levels
> is itself externally validated against real IGS SP3 geometry."*

The honesty mechanism that makes this a *benefit* claim and not a marketing claim: the **same
engine** produces both the baseline and the uploaded-config number, the delta is reproducible,
and the optimism of any ML-detection benefit is bounded by WP-B's distribution-shift report
(`distribution_shift_report`, `kshana/src/impairment_eval.rs`) — so the benefit case reports
its own ceiling.

## 7. Honest residuals

1. **Every number here is modelled / representative.** No figure is a validated NAVEX
   performance number and no real constellation is designed. The streets-of-coverage example
   (20 180 km → 8 satellites) is a hand-verified *method* demonstrator, not a LEO IOD design.
2. **The seam-exact minimum-satellite solver is a follow-on.** The idealised estimate can
   under-count the real minimum by a plane at the counter-rotating boundary (documented in the
   capability map); the seam-sensitive Rider solver is roadmap.
3. **Multi-constellation DOP is not yet cross-checked against an external reference tool**
   (e.g. gnss-rtk); the geometry rides on the validated SGP4 core but the DOP comparison oracle
   is a follow-on.
4. **Reconfigurability hardware, the reconfiguration mechanism, secure in-orbit update, the
   payload/SDR, the bus, and the platform/business model are partner- or programme-owned** —
   out of WP-A scope. Ashforde quantifies the *PNT benefit* of reconfigurability, not the means.
5. **TRL ~3, no flight heritage, no certification, no ESA endorsement.** "Validated" is reserved
   strictly for external-oracle checks (here only the RAIM/ARAIM core qualifies); everything
   constellation-sizing-related is "modelled".
6. **Consortium-/founder-gated items** (the seat, the prime, the real SoW SRD, mission inputs,
   costing, the German registered office) are not pre-decided here; this note is the method asset.
