# Kshana 0.40 release video

The 0.40 release in about 84 seconds: the Artemis-class mission thread and the trajectory comparisons that missed, evidence labels, measured clocks and data-partner checks, the emitter region, the benchmark re-campaign, seventeen languages beside English, and the ledger. It uses the same format as the 0.38 + 0.39 set in `docs/handover-0.39/video/`. There are four videos: a 1920×1080 promo (84 s, 30 fps, h264), the same with the brand strip, a 1080×1080 showcase, and a 1080×1350 (4:5) feed cut from the same scenes. Each has a poster.

Every number on screen is read from `src/data/numbers.json`. That file is built from the engine output committed at kshana tag `v0.40.0` (commit `1395dc68`). **The numbers were not re-run for the video.** Building and running the engine was not permitted in the environment where the video was made, so `src/collect.py` reads the outputs the repository itself commits at the tag: the Studio's recorded mission-thread run, the emitter-region example, the pre-registered results under `xval/` and `tests/fixtures/`, the verification matrix and the i18n catalogues. `NUMBERS.md` lists each file, its SHA-256 and the values taken from it, and the commands that regenerate them from a build. Synthetic inputs (the emitter-region reports and the partner submission) say so on screen.

## Rebuild

1. Check out kshana at tag `v0.40.0`.
2. `python3 src/collect.py --engine <kshana> --out src/data/raw` reads the committed outputs and records their hashes.
3. `python3 src/build_numbers.py` writes `src/data/numbers.json` and `NUMBERS.md`.
4. Render with `node src/render.mjs --variant promo --out kshana-0.40-promo-1920x1080.mp4`, and the same for `branded`, `showcase` and `feed`. `--still <seconds>` writes one frame, and `--check 1` tests that every scene fits its box. This step needs Playwright with Chromium (set `CHROMIUM=<path>` to use a specific binary) and ffmpeg. The scenes are `src/index.html`, `style.css` and `video.mjs`. Each frame is a pure function of the time, so the output is deterministic.
5. Posters: `--still 16` (promo and branded, the mission thread), `--still 56` (showcase and feed, the emitter region).

To re-run the engine instead of reading committed output, build the tag (`cargo build --release --bin kshana`) and run the commands under "Live commands" in `NUMBERS.md`. Then replace the matching entries in `raw.json`.

`src/data/raw/` is not committed (it is regenerated by step 2). The fonts are Geist, Geist Mono and Unbounded, copies of the site's own, plus subsets of Noto Sans JP and Noto Sans SC that hold only the characters of the two advisory lines on screen (all SIL Open Font License). The mark is a copy of the site's own.

## What is on screen

- The advisory line is on every frame.
- MODELLED appears wherever a figure is modelled, and the mission-thread inputs are marked illustrative.
- The Artemis I and CAPSTONE comparisons are shown as NOT MET, the LRO comparison as met, the Jammertest 2025 comparison of the emitter region as NOT ASSESSABLE, and A2, D1 and R1 as NOT MET.
- The languages are labelled as machine translation, with English as the reference.
- The ledger is shown as 401 rows: 176 VALIDATED, 221 MODELLED and 4 PARTNER.
- There is no agency branding and no claim of endorsement. "Artemis-class" names the example. Artemis I, CAPSTONE and LRO appear only as the public trajectories the propagators were compared against.
- The RUSTSEC-2026-0387 dependency fix is in the CHANGELOG's [0.39.0] section, not [0.40.0], so it is not presented as a 0.40 feature. The close names the minimum Rust, 1.88.
- The Studio and site were not screenshotted: serving and running the tag's `web/` was also not permitted here. The mission-thread chart and the emitter-region map are drawn from the committed result files.
