## What exists (all tested on the 0.39 tree with the pseudo-locale `en-XA` and one real German proof)

Catalogues in kshana `i18n/en/`:
- `ui.ftl` (hand written; 515 messages incl. 413+10 generated `studio-<page>-<slug>` static Studio text), `glossary.ftl` (terms, `-advisory` family, `-mt-notice`);
- `pages/*.ftl` (generated by `extract`, 18,786 distinct segments, ids `seg-<sha12>`; `_shared.ftl` holds segments on 25+ pages; `_index.json` maps page to ids);
- `studio-js.ftl` (4,271) and `site-js.ftl` (650): generated by `jsx` from the `t(id, english, vars)` call sites (the English lives in the code);
- `studio-pages.ftl` (333): Studio static text with inline markup, generated by `studio-pages` (HTML carries `data-l10n-rich` and `data-l10n-tags`);
- `data.ftl` (3,099): prose of the JSON and generated JS data modules listed in `i18n/data-spec.json`, ids `dat-<sha12>`;
- `engine.ftl` is W55/W58's (`i18n/engine-0.40`), not mine.

`tools/i18n.mjs` commands: `extract`, `images`, `apply <lang…>`, `verify <lang…>`, `english`, `sitemaps`, `langs`, `size`, `pseudo`, `check`, `status`, `todo`, `merge`, `migrate`, `jsx`, `studio-pages`, `data`, `csslint`. `tools/i18n-fonts.py` (CJK subsets), `tools/i18n-negotiation-test.mjs`, `tools/i18n-pseudo-test.mjs`, `tools/i18n-identity-test.mjs` (Playwright; need `NODE_PATH` to a playwright install, e.g. `/opt/node22/lib/node_modules`).

Build pipeline (the order matters; it is the translation step of `pages.yml`): `images --tree site` (inlined images become `assets/img/<sha12>.*`, HTML 40 MB to 14 MB) then `langs --min 0.25` then `apply <langs> --src site --out site --langs <langs>` (pages, notices, hreflang, `/<lang>/studio/` stubs, translated data copies, per-language sitemap) then `fonts` (ja, zh-Hans) then `verify <langs> --src site --dist site` then `sitemaps` then `english --src site --langs <langs>` (switcher, detection script, hreflang on English pages) then `size --cap 500`. A language is built only at 25 % of segments; with none built the English pages are untouched.

What `verify` fails on, per page: numbers (digit runs), code spans, link targets, the machine-translation notice, tier, verdict and status token counts, every English "type-approved" still said, the engine-legal and `-advisory` sentences exact. `check` fails per catalogue file on syntax, variables, string literals, tags, digits, plural categories, glossary rendering and per-message caps-token counts. `merge` applies the same message checks before writing.

Runtime: pages load `/studio/lib/l10n-boot.mjs` (translated site pages via `apply`, all Studio pages via the HTML); `window.kshanaL10nReady` resolves when the first catalogue is loaded and page scripts `await ready()` (4 s timeout). `t()` falls back to the English at the call site. `fetchData` / `importData` (lib/t.mjs, site js/t.mjs) load `/<lang>/<file>` for the JSON and data modules when it exists.

5. Moved ids: the translators run `node tools/i18n.mjs migrate <lang> --from-rev <rev their ids came from>`; it carries translations whose English text is unchanged and keeps the rest in `i18n/<lang>/_orphans.txt`.
6.
