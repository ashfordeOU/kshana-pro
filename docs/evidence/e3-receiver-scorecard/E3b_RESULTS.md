## Implementation notes (decided before the held-out campaign was generated; disclosed)

* **Arrival-time stamping of an analogue.** The open reader groups NMEA sentences by their
  **stated** time, so a time spoof can merge two emitted epochs (development: 1,501 emitted, 1,499
  read on the E3 time-spoofing case). v2 therefore scores one epoch per emitted epoch: each is
  stamped with the generator's epoch time, its fix and the receiver's own flags are read from that
  epoch's own sentences, the truth is taken at that time, and event windows are taken on the same
  arrival clock. The open monitor's alarm is the one of the stream epoch with the same stated time.
  Found and fixed on development data (E3 public campaign) before `E3b_dev.json` was committed.
* **Campaign format.** Besides `analogue_seed`, two additions were needed and are disclosed: an
  optional top-level `method` (default v1, so the published E3 v1 sample still reproduces byte for
  byte), and `library` may name a file in the threat library's format relative to the campaign
  (the five new analogues live in `examples/scorecards/e3b-analogues/` and are not added to the
  library edition). The scorecard format (`kshana-pro-receiver-scorecard/1`) is unchanged.
* **Log cases under v2.** This campaign format carries no host arrival timestamps for a log, so v2
  does not score a log case's errors and says so in the scorecard's limits (the pre-registration's
  rule). The held-out campaign has no log cases.
* **Scoring route.** The held-out scorecard was produced and signed by the test (the same
  `scorecards::score`, `report::write_dir` and `signed_dossier::sign` the CLI calls), because a
  release build's CLI needs a licence; the demo key's secret is not committed.

The E3 sample result (E3-B2 (a) missed on 5 of 15 events with v1) stays published in `RESULTS.md`.
These are test results of the scorecard method on synthetic analogues and a modelled receiver,
not statements about any product.
