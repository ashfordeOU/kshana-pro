## Done on #45, with the tests that pin it

  `docs/design/LOOP-DESIGN-TOML.md`). The hash is SHA-256 over a canonical JSON form (keys
  sorted at every level, fixed number form; `canonical_json`). The default's hash is pinned
  in `iq::track::design::tests::the_builtin_default_hash_is_pinned` (with PIN-SCOPE lines;
  `tests/source_guards.rs` requires them). **Any change to a default changes the hash.**
  Re-pin the test, LOOP-DESIGN-TOML.md and CHANGELOG, and tell the coordinator (W7 and W3
  pin to it).
- **Streaming epoch record** `kshana.track-epoch/1` (CSV, JSONL, binary 184 B), `Summary`,
  events, and the bounded-memory test `tests/iq_track_memory.rs`.
- **Lock state machine** (`src/iq/track/lock.rs`): false-lock check in every tracking
  state, and a time-based re-acquisition window. The defaults are `reacq_window_s` 30 and a
  FIXED `reacq_interval_s` 0.1 s (coordinator decision: the retry schedule must not
  inflate measured re-acquisition time). Back-off is optional: set
  `reacq_max_interval_s` above the interval. `max_reacq_attempts` is an optional cap,
  default 0. Tests:
  - `a_signal_gap_is_lost_then_reacquired` (0.3 s bar);
  - `every_channel_recovers_from_a_2_s_outage` (W3's scenario, release, ignored);
  - `the_summary_final_state_follows_the_last_transition` (a retirement decided in the
    search step, `max_reacq_attempts = 2`, so only the event can set RETIRED);
  - `a_false_lock_is_detected_at_the_alias_and_repaired_by_reacquisition`;
  - `an_unsearchable_rate_tracks_without_the_check`.
- **FLL assist with hysteresis**: `[design.carrier] fll_assist = "pull-in"` (default) or
  `"always"` (bit-identical to before). Keys: `fll_off_pli = 0.8`, `fll_on_pli = 0.6`,
  `fll_gate_dwell_s = 0.1`, validated `on < off`. Rust: `LoopConfig.fll_assist`
  (`FllAssist::{PullIn(FllGate), Always}`), `LoopCore::set_fll_enabled`,
  `EpochOutput.fll_active`. Tests:
  - `the_fll_gate_holds_phase_lock_at_35_dbhz` (debug; fails with "always");
  - `the_default_design_pulls_in_a_100_hz_handoff_error` (B4, both modes, no false lock
    and no pull-in timeout);
  - `carrier_lock_bars` (B1–B3 plus no toggles, release, ignored);
  - surveys `carrier_lock_survey` and `fll_handover_survey` (release, ignored, print only).
- **`final_state`** in `--summary` and the table comes from `ChannelSummary.final_state`
  (the last of epoch state and event).
- **`commensurate_sampling` warning** (`iq::track::commensurate_samples_per_chip`, any rate

## Pre-registrations

- **DLL jitter** (`docs/design/evidence/dll-jitter/`, pre-registered at `a60ad599`):
  P1/P2/P3 all PASS and are asserted by `dll_jitter_bars` (release, ignored). The root cause
  is commensurate sampling (`commensurate_sampling_turns_the_dll_s_curve_into_a_step`, debug).
- **Carrier lock** (`docs/design/evidence/carrier-lock/`, pre-registered at `a4119ba7`):
  H1 holds (the always-on 10 Hz FLL injects frequency noise). B1–B4 PASS for "pull-in" and
  the before/after tables are in RESULTS.md. **Open limitation:** at 35 dB-Hz the hand-over
  comes 1.9–2.6 s into the track, and at 33 dB-Hz the FLL keeps the PLI below 0.8 so pull-in
  never completes, for any threshold pair from (0.8, 0.6) down to (0.6, 0.4). Lower
  thresholds chatter at 37 dB-Hz (3 toggles at 0.6/0.4). Candidate next steps, each to be
  pre-registered: a narrower default FLL (e.g. 2–5 Hz), or a time-limited FLL pull-in
  followed by PLL only.

## Commensurate sampling: data for the warning rule

`spacing_ratio_survey` (release; `KSHANA_SURVEY_SPC`, `KSHANA_SURVEY_D` and
`KSHANA_SURVEY_DOPPLER` select the grid). σ_ε excess over an incommensurate control
(1.0731× the rate, same d) at 45 dB-Hz and 1500 Hz Doppler:

| spc | d = 0.5 | d = 0.25 | d = 0.1 |
|---|---|---|---|
| 2 | 30.1 | 24.8 | 11.7 |
| 2.5 | 4.5 | 8.4 | 9.5 |
| 3 | 8.1 | 16.4 | 10.6 |
| 3.5 | 1.9 | 1.45 | 6.6 |
| 4 | 0.88 | 10.4 | 8.1 |
| 5 | 4.2 | 8.4 | 6.2 |
| 6 | 4.0 | 3.8 | 6.6 |
| 8 | 0.70 | 0.88 | 4.3 |
| 16 | 0.77 | 1.02 | 1.16 |

The result depends on Doppler, because code Doppler slides the sampling pattern:
- At **0 Hz**: (4, 0.5) is 2.0× with a +0.011 chip mean; (4, 0.25) has a +0.125 chip bias;
  (3.5, 0.5) is 1.6× with −0.012 mean; (3.5, 0.25) is 2.5× with +0.006.
- At **4000 Hz**: (4, 0.5) 1.0×, (3.5, 0.5) 1.2×, (3.5, 0.25) 1.1×, (4, 0.25) 4.9×.

Decision so far (coordinator, 21:28): a measured table keyed on (spc, d), with a
"not characterised" note outside it. Because of the 0 Hz rows, **4.092 MHz with d = 0.5 is
not safe to exempt**: a near-zero-Doppler satellite gets 2× error and a bias. The shipped
warning therefore still fires at every commensurate rate. Remaining work: put the measured
excess into the warning text (by (spc, d), worst case across Doppler) and add the "not
characterised" note for pairs outside the table. 8 and 16 spc at Doppler 0 are not
measured yet; measure them before exempting anything.

Coordinator's alternative suggestion was a run-time S-curve rule: evaluate the noise-free
S-curve over ±d/2 at several sub-sample phases and warn on slope deviation or flat steps.
I modelled it (scratch, not committed) and it does **not** reproduce the measurements:
- (4, 0.5) has a 49%-of-d flat step yet measures 0.88× at 1500 Hz;
- (5, 0.5) and (3.5, 0.5) have near-ideal slopes yet measure 4.2× and 1.9×.

The loop dynamics, noise and Doppler sliding matter, so the table is the right tool.
