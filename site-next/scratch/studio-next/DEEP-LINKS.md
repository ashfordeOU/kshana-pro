# Kshana Studio: deep links

Generated by `tools_links.mjs` in the Studio staging copy (`explorations/2026-09-30-studio-next/`) from the scenario catalogue, the recorded results and the native engine's recordings. Do not edit by hand: run `node tools_links.mjs` again.

## The pattern

`<studio>/index.html?scenario=<file without .toml>&tab=<view>`, where `<studio>` is `playground/` on the site (the path the site's "Open in Kshana Studio" links already use). The scenario loads, runs in the browser and opens on the named view. Add `&embed=1` for the chrome-free embed.

Optional extras:

- `&play=1` starts the replay of a waterfall, a mission timeline or a coverage map (not under reduced motion).
- `&frame=<id>` picks the waterfall of a spectrum run (`band` or `panel-0`, `panel-1`, ...).
- `&field=<key>` picks the mapped field of a coverage map.
- `&view=<id>` picks the solar-system drawing (`planets`, `inner`, `moons:<Body>`).

Views (`tab=`): `spectrum` (Spectrum), `solar` (Solar system), `body-pnt` (Relay positioning), `coverage` (Coverage), `campaign` (Campaign), `leo-signal` (Signal design), `leo-pass` (Pass & link), `leo-navmsg` (Navigation message), `leo-positioning` (Positioning), `leo-chain` (End-to-end chain), `llr-datum` (Laser-ranging datum), plus `animation`, `report` and `exports` for every scenario that has them, and the older views `overview`, `timeseries`, `signal`, `holdover`, `masks`, `stability`, `orbit`, `ground`, `sweep`, `json`.
