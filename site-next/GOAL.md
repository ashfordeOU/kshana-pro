## Standing rules
- Every visual is real engine output (engine version + scenario + seed), reproducible in Kshana Studio with one click. Nothing is "Illustrative".
- Planets and moons use real imagery everywhere.
- No prices. Paid tiers end in contact buttons only (contact@ashforde.org).
- Pro claims stay within the public facts. Nothing from kshana-pro is disclosed.
- Every abbreviation is spelled out at first use; the glossary lives in Docs.
- Git: ashfordeOU identity, no trailers, no AI or vendor names, no "Aperio", never --no-verify, never stash/reset/clean.
- The site audit loops until nothing is left (founder, 2026-09-28: "Site audit should keep happening until every last piece is fixed and built and verified. Nothing is left unverified"). Every audit round fixes what it finds, rebuilds, and re-runs the full audit; the loop stops only on a clean round with zero issues. Every page, section, Studio control, export, link and claim is verified by a real run or a real check, never by an agent's say-so. Anything that cannot be verified is removed or reported, never shipped.
- Display matrix (founder, 2026-09-28: "screen sizing… mobile? custom? full screen? big and small all possibilities? user adjusted screen size? color correctness in dark and light modes making sure nothing is not readable or visible"). Every audit round runs ALL of this on every page and every Studio view. A round is clean only with zero issues across the whole matrix.
  - Fixed devices:
    - phones 320×568, 360×740, 375×667, 390×844, 414×896, 430×932
    - phones in landscape 568×320, 667×375, 844×390, 932×430
    - tablets 768×1024, 820×1180, 1024×1366, both portrait and landscape
    - laptops 1280×720, 1280×800, 1366×768, 1440×900, 1536×864
    - desktops 1920×1080, 2560×1440, 3840×2160
    - ultrawide 3440×1440
  - Continuous width sweep: every 10 px from 280 to 2560 at two heights (900 and 500). No horizontal scroll, no overlap, no clipped text, no element outside the viewport, at every step.
  - Short and tall windows: heights 400, 500, 600, 800 and 1600 at widths 1024 and 1440. Nothing important is hidden behind fixed bars.
  - User resizing live: shrink and grow the window while the page (and a Studio run) is open. Charts, canvases, the globe and planets re-layout correctly, with no stale sizes, blank canvases or console errors.
  - Zoom and text size: browser zoom 50%, 80%, 100%, 125%, 150%, 200%, 300% and 400%; text-only enlargement to 200%. Content reflows at 320 CSS px with no loss of content or function (WCAG 2.2 1.4.4, 1.4.10, 1.4.12 text spacing).
  - Full screen: the Fullscreen API on the globe, planets, charts and Studio, entering and exiting, plus the browser full-screen window size.
  - Themes, all three states: system (no data-theme stamp) under both prefers-color-scheme light and dark, explicit data-theme="light", and explicit data-theme="dark"; the toggle both ways, mid-page.
  - Colour correctness in every theme:
    - WCAG AA contrast for all text (4.5:1, and 3:1 for large text), measured on the real computed background, including over images and gradients
    - 3:1 for non-text UI and chart marks, lines, gridlines-that-carry-meaning, legends, icons and focus rings (1.4.11)
    - no text or mark invisible against its ground
    - SVG and canvas charts are checked by sampling rendered pixels, not only CSS
    - chart palettes stay distinguishable under protanopia, deuteranopia and tritanopia simulation
    - semantic colours (good, warning, critical) are never colour-only
    - forced-colors / Windows high-contrast mode stays usable
  - Motion: prefers-reduced-motion on and off; nothing required is hidden behind an animation.
  - Input: keyboard only (visible focus everywhere, no traps), touch targets at least 24×24 CSS px on phones (2.5.8), hover-free use on touch.
  - Browsers: Chrome, WebKit (Safari engine) and Firefox via Playwright. A real iOS Safari check uses the iOS simulator if available, and otherwise WebKit mobile emulation, stated as such.
  - Tool: explorations/2026-09-27-audit/matrix/run_matrix.mjs (--quick while working, --full for every audit round). Until it exists, extend the old tool to this matrix; never fall back to 5 viewports.
  - Evidence per round: the tool, the matrix size, the issue count per category, and screenshots of every page at the key sizes in both themes.
- CI and every process stay verified green through to the end (founder, 2026-09-28: "The CI and all processes also should be verified until green up until the end"). Locally, before any commit counts:
  - the prescreen of every test binary
  - scripts/gate.sh
  - clippy and fmt
  - the web/*.test.mjs suite and smoke test
  - site check.py and selfcheck
  - the feature register check
  - the site audit loop

  After any push: every GitHub Actions workflow run is watched to completion, and every one must be green. A red is fixed at its cause and re-run until green, never skipped, retried blind or worked around. Nothing is reported done while any run is red, pending, or unchecked.
